# Software Requirements Specification (SRS)
## Pose2Skill-Robot — نظام نقل المهارات البشرية للروبوتات

**الإصدار**: 1.0  
**التاريخ**: 2026-10-01  
**المرجع الأكاديمي**: مشروع تخرج — جامعة [اسم الجامعة]  
**المعيار المستخدم**: IEEE 830 SRS Standard

---

## 1. مقدمة (Introduction)

### 1.1 الغرض (Purpose)
توثق هذه الوثيقة المتطلبات الوظيفية وغير الوظيفية الكاملة لنظام **Pose2Skill-Robot**، وهو نظام برمجي روبوتي ذكي يقوم باستخلاص المهارات الحركية من عروض الفيديو البشرية وتنفيذها على أذرع روبوتية داخل بيئات المحاكاة.

### 1.2 النطاق (Scope)
| البُعد | التفاصيل |
|--------|----------|
| **النظام** | Pose2Skill-Robot v1.0 |
| **الاستخدام الأساسي** | تعليم الروبوت مهام التلاعب من فيديو بشري |
| **المستخدمون** | باحثون، مهندسو روبوتات، طلاب الدراسات العليا |
| **البيئة** | Ubuntu 22.04 + ROS 2 Humble + Gazebo Harmonic |
| **الروبوتات المدعومة** | Franka Emika Panda (7-DoF), Universal Robots UR5e (6-DoF) |
| **خارج النطاق** | روبوتات ثنائية الأرجل، الأجسام المرنة، البيئات الخارجية |

### 1.3 التعريفات والمختصرات (Definitions)
| المصطلح | التعريف |
|---------|---------|
| **LfD** | Learning from Demonstration — التعلم من العروض |
| **HOI** | Hand-Object Interaction — تفاعل اليد مع الأجسام |
| **EE** | End-Effector — أداة النهاية الروبوتية |
| **IK** | Inverse Kinematics — الحركية العكسية |
| **Skill Graph** | الرسم البياني الزماني-المكاني للمهارة |
| **Affordance** | الإتاحة — الخصائص الوظيفية القابلة للاستغلال في جسم ما |
| **ST-GCN** | Spatio-Temporal Graph Convolutional Network |
| **DoF** | Degrees of Freedom — درجات الحرية |
| **CETI** | Cross-Embodiment Transferability Index |
| **SR** | Task Success Rate — معدل نجاح المهمة |
| **TCT** | Task Completion Time — زمن إنجاز المهمة |

## 2. الوصف العام للنظام (Overall System Description)

### 2.1 المنظور العام (System Perspective)
```
┌─────────────────────────────────────────────────────────────┐
│                    Pose2Skill-Robot System                  │
│                                                             │
│  ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌─────────┐ │
│  │  Video   │──▶│Perception│──▶│  Skill   │──▶│Planning │ │
│  │  Input   │   │  Layer   │   │Extraction│   │& Exec.  │ │
│  └──────────┘   └──────────┘   └──────────┘   └────┬────┘ │
│                                                     │       │
│  ┌──────────────────────────────────────────┐       │       │
│  │        Web Dashboard (React)             │◀──────┘       │
│  └──────────────────────────────────────────┘               │
│                                                             │
│  ┌──────────────────────────────────────────┐               │
│  │     Gazebo Simulation Environment         │               │

└─────────────────────────────────────────────────────────────┘
```

### 2.2 وظائف النظام الرئيسية (Major System Functions)
1. **F1 — استقبال الفيديو البشري**: معالجة مقاطع RGB/RGB-D من كاميرا عادية أو RealSense
2. **F2 — الإدراك ثلاثي الأبعاد**: استخراج إحداثيات الجسم والأيدي والأجسام
3. **F3 — التجزئة الزمنية**: تصنيف الحركة إلى 7 أفعال أولية
4. **F4 — بناء Skill Graph**: توليد الرسم البياني المستقل عن التجسيد
5. **F5 — التعيين الحركي**: ترجمة Skill Graph إلى أهداف EE للروبوت
6. **F6 — التخطيط الحركي**: توليد مسارات خالية من التصادم
7. **F7 — التنفيذ والتقييم**: تشغيل المسار في Gazebo وقياس الأداء
8. **F8 — لوحة التحكم**: واجهة ويب تفاعلية للمراقبة والتحكم

## 3. المتطلبات الوظيفية (Functional Requirements)

### FR-01: معالجة مدخلات الفيديو
| المعرّف | FR-01 |
|---------|-------|
| **العنوان** | استقبال ومعالجة مدخلات الفيديو |
| **الأولوية** | Must Have |
| **الوصف** | يجب أن يقبل النظام مدخلات الفيديو بالصيغ: MP4, AVI, MOV (من ملف)، أو بث مباشر من كاميرا ويب أو RealSense D435i |
| **معايير القبول** | - دعم دقة 640×480 كحد أدنى<br>- معالجة ≥25 إطار/ثانية<br>- دعم RGB وRGB-D |

### FR-02: تقدير وضعية الجسم
| المعرّف | FR-02 |
|---------|-------|
| **العنوان** | تقدير الهيكل العظمي ثلاثي الأبعاد |
| **الأولوية** | Must Have |
| **الوصف** | يستخرج النظام إحداثيات 17 مفصل رئيسي من الهيكل العظمي البشري في الفضاء ثلاثي الأبعاد |
| **معايير القبول** | - دقة ≥90% على COCO dataset<br>- FPS ≥25 على GPU RTX 3060<br>- نشر على `/pose2skill/body_keypoints` |

### FR-03: تقدير وضعية اليد
| المعرّف | FR-03 |
|---------|-------|
| **العنوان** | استخراج هندسة اليد وحالة القبضة |
| **الأولوية** | Must Have |
| **الوصف** | يستخرج النظام إحداثيات 21 نقطة في اليد مع قياس انحناء الأصابع وحالة فتح/إغلاق القبضة |
| **معايير القبول** | - دقة كشف الإمساك ≥95%<br>- خطأ تحديد وقت الإمساك < ±3 إطارات |

### FR-04: كشف وتتبع الأجسام
| المعرّف | FR-04 |
|---------|-------|
| **العنوان** | كشف الأجسام وتقدير وضعيتها السداسية |
| **الأولوية** | Must Have |
| **الوصف** | يكشف النظام الأجسام المستهدفة ويتتبعها عبر الإطارات مع تقدير موقعها واتجاهها في الفضاء |
| **معايير القبول** | - ADD-S metric < 10% diameter<br>- حفاظ على معرّف الجسم عبر الإطارات (Re-ID) |

### FR-05: التجزئة الزمنية للأفعال
| المعرّف | FR-05 |
|---------|-------|
| **العنوان** | تصنيف الحركة إلى أفعال أولية |
| **الأولوية** | Must Have |
| **الوصف** | يقسّم النظام الحركة المستمرة إلى 7 أفعال أولية: Approach, Reach, Grasp, Lift, Transport, Place, Release |
| **معايير القبول** | - دقة التصنيف ≥90%<br>- F1-Score ≥0.85 لكل فعل |

### FR-06: بناء الرسم البياني للمهارة
| المعرّف | FR-06 |
|---------|-------|
| **العنوان** | توليد Spatio-Temporal Skill Graph |
| **الأولوية** | Must Have |
| **الوصف** | يبني النظام رسماً بيانياً (G_S = ⟨V, E, C⟩) يمثل المهارة بشكل مستقل عن هيكل المنفذ |
| **معايير القبول** | - يعالج ≥1 عرض بشري<br>- يُحفظ بصيغة YAML/JSON<br>- يشمل قيود الإتاحة |

### FR-07: التعيين الحركي الروبوتي
| المعرّف | FR-07 |
|---------|-------|
| **العنوان** | تحويل Skill Graph إلى أهداف EE |
| **الأولوية** | Must Have |
| **الوصف** | يترجم النظام وضعيات الرسم البياني إلى وضعيات هدف لأداة النهاية الروبوتية في إطار الروبوت |
| **معايير القبول** | - يدعم Franka Panda (7-DoF) وUR5e (6-DoF)<br>- خطأ الوضعية < 5mm |

### FR-08: التخطيط الحركي الآمن
| المعرّف | FR-08 |
|---------|-------|
| **العنوان** | توليد مسارات خالية من التصادم |
| **الأولوية** | Must Have |
| **الوصف** | يستخدم النظام MoveIt 2 + OMPL لتوليد مسارات حركية تحترم قيود المفاصل وتتجنب التصادمات |
| **معايير القبول** | - صفر تصادمات في بيئة محكومة<br>- زمن التخطيط < 5 ثوانٍ<br>- Jerk أقل من Baseline 1 و 2 |

### FR-09: تنفيذ المحاكاة والتقييم
| المعرّف | FR-09 |
|---------|-------|
| **العنوان** | تشغيل وتقييم المهارة في Gazebo |
| **الأولوية** | Must Have |
| **الوصف** | ينفذ النظام المسار الحركي في Gazebo ويسجل مقاييس الأداء (SR, TCT, Jerk, CETI) |
| **معايير القبول** | - يدعم 4 مهام معيارية<br>- يسجل النتائج بصيغة CSV<br>- يولد تقرير مقارنة تلقائي |

### FR-10: لوحة التحكم التفاعلية
| المعرّف | FR-10 |
|---------|-------|
| **العنوان** | Web Dashboard للمراقبة والتحكم |
| **الأولوية** | Should Have |
| **الوصف** | توفر الواجهة رؤية تزامنية للفيديو الأصلي، Skill Graph، وأداء الروبوت في المحاكاة |
| **معايير القبول** | - تأخير WebSocket < 200ms<br>- عرض ثلاثي الأبعاد للـ Skill Graph<br>- لوحة مقاييس حية |

## 4. المتطلبات غير الوظيفية (Non-Functional Requirements)

### NFR-01: الأداء (Performance)
| المعيار | القيمة المستهدفة |
|---------|-----------------|
| معدل معالجة الإطارات (FPS) | ≥ 25 FPS على GPU RTX 3060 |
| زمن بناء Skill Graph | < 10 ثوانٍ لعرض مدته 30 ثانية |
| زمن التخطيط الحركي | < 5 ثوانٍ لكل فعل أولي |
| زمن استجابة Dashboard | < 200ms (WebSocket) |

### NFR-02: الموثوقية (Reliability)
- معدل نجاح المهمة ≥ 85% في بيئة محاكاة محكومة
- CETI ≥ 85% عند النقل بين Franka وUR5e
- التعامل مع انقطاع الكاميرا لمدة < 0.5 ثانية دون إعادة تشغيل

### NFR-03: قابلية الصيانة (Maintainability)
- تغطية الاختبارات (Test Coverage) ≥ 80%
- توثيق كامل لجميع APIs
- Modularity: إمكانية استبدال أي نموذج (مثل RTMPose) دون تعديل طبقات أخرى

### NFR-04: قابلية التوسع (Scalability)
- إضافة روبوت جديد عبر ملف YAML واحد فقط
- إضافة مهمة جديدة دون تعديل كود النواة

## 5. قيود وافتراضات النظام (Constraints & Assumptions)

### 5.1 القيود (Constraints)
- الأجسام المدعومة: أجسام صلبة فقط (لا أجسام مرنة أو سائلة)
- بيئة التصوير: إضاءة مقبولة ومستقرة، لا احتجاب كامل لليدين
- مدة عرض الفيديو: بين 5–120 ثانية
- الحد الأقصى للأجسام: 5 أجسام متزامنة في المشهد

### 5.2 الافتراضات (Assumptions)
- الكاميرا ثابتة خلال تسجيل العرض (Eye-to-Hand setup)
- الجسم موجود في مساحة عمل الروبوت (Reachable Workspace)
- الديناميكية شبه ثابتة (Quasi-static) — لا حركات بالستية سريعة
